# 本育成の自動編成と起動時の更新

2026-10-20実装。SSRたづなは自前6枠目、レンタルは5枠目。本育成の候補はSSRのみ。

## 自動設定

キャラ選択時には適性が最も高い脚質を初期選択する。同程度なら現在の脚質を保持する。脚質はその後自由に変更でき、キャラ・脚質・レースを変更するたびにサポカと金スキル側のイベント択を組み直す。ページ起動時にも、保存されていた手動編成を最新の推奨へ更新する。

本育成の準備チェックや因子周回データは維持する。チェックや検索だけでは本育成の編成を変更しない。サポカ・イベント択を直接変更した場合は「手動調整中」とし、同じ条件で作業中は保持する。「推奨に戻す」では再設定する。保存プランの明示的な読み込み・JSON読み込みでは、その保存編成を読み込む。次の条件変更またはページ起動時には自動設定へ戻る。

## 選定の根拠

`main-deck-data.js` のレビュー済み編成例を起点にする。2026年10月20日に当該開催のGameWith記事を照合。両長距離イベントの例は同じだが、コースごとの出典と条件を分ける。京都の主加速評価はユーザー指定のウマ娘ラボを維持し、noteの因子設計に記載された本育成の想定・賢さヤングの採用理由も参照する。

- [11月京都3000mの編成例](https://gamewith.jp/uma-musume/article/show/574934)
- [12月中山2500mの編成例](https://gamewith.jp/uma-musume/article/show/578925)
- [ウマ娘ラボ：11月のコースと主加速](https://umamusumelabo.com/event/loh/loh-kyoto3000-202611)
- [note：dai、11月先行因子設計](https://note.com/light_bear2389/n/n6bb1895d9c7d)
- [note：dai、11月逃げ因子設計](https://note.com/light_bear2389/n/n4767c0507205)

先行・追込のスピード3枚型など、編成例の種類配分を保つ。同キャラの重複と育成本人のサポカを除き、自前覚醒で取れる金、脚質・距離・バ場に合う金、主加速の不足を評価して代替を探索する。同じイベントの相反する択は同時計上せず、金と交換する白スキル択を本育成に採用しない。真髄体を取るためにパワーファインを採用する処理はない。育成性能のシミュレーション・所持・凸数の最適化ではなく、公開編成例と取得経路を用いる推奨案である。

詳細未発表の開催では、距離区分・バ場・脚質から「暫定編成」を設定する。未発表の競馬場・天候やコース別スキルは作らない。元記事も新シナリオ実装前の暫定編成と説明しているため、現段階はユーザー指定のトレセン軒・たづな固定を継続する。

## 最新データの反映

`data/live-planner.json` に開催条件、推奨スキル、優先度、出典、編成候補を一括で収録する。ページ起動時と「最新情報を更新」で取得する。リクエストにはキャッシュ回避のパラメーターと `cache: no-store` を付け、成功した検証済みデータをブラウザーへ保存する。通信失敗や互換性のない更新では、前回の検証済みデータ、次いで同梱データを使い、画面に取得状態を表示する。部分的に壊れた更新を適用しない。

追加発表を反映する際は `recommendations.js` の開催条件・推奨・出典、`priorities.js` の優先度、`main-deck-data.js` の編成候補と確認日を根拠に沿って更新し、`npm run data:live` を実行する。公開ワークフローも配信データを生成・検証してからデプロイする。公開後はページ起動または更新ボタンで取得し、開催表示、編成、金スキル択、不足因子を一緒に再計算する。

攻略サイトや公式告知の内容を無人で解釈して最適と認定する機能ではない。新しい情報は確認して配信データへ追加する必要がある。この境界はアプリの「データ・出典」にも明記する。
