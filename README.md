# UMAPLAN

ウマ娘の対人戦に向けて、コース・作戦・育成キャラ・サポート編成からスキルと継承・白因子の準備を整理するWebアプリです。

**[アプリを開く](https://io-io-315md.github.io/uma-skill-planner/)**

2026-10-28：駿大祭とSSR吾妻・パワーマヤノへ更新。[更新内容・根拠](docs/shuntaisai-update.md)

## 使えること

- 11月京都芝3000m LoH、12月中山芝2500mチャンミのコース別スキル候補
- 本育成欄の上の「有力ウマTier」から、11月の11衣装のS・A・B表を表示。note 2名と指定のウマ娘ラボ記事を比較し、理由・評価差・出典の公開日を確認して本育成に選択。12月は新しい比較記事が不足するため評価保留
- 全272衣装の育成キャラ、566枚のサポートカードの照合。覚醒は各キャラの最大Lvで判定
- ウマ娘・サポカの全選択画面でキャラ名の部分一致検索。ひらがな・カタカナ・半角カナを同じ名前として照合し、衣装名・カードのタイトルは検索対象から除外
- 本育成のサポカ選択はSSRのみ、因子周回はSSR・SR・Rを選択可能。いずれも実装日の新しい順で、各カードに実装日を表示
- 本育成は「短距離・マイル・中距離・長距離・ダート」と「逃げ・先行・差し・追込」で用途を絞り込み。レースと作戦を初期設定し、汎用カードも自動で含める。各カードで金スキル・ヒント・対象条件を確認可能
- 本育成と駿大祭の因子周回は6枠目にSSR吾妻を固定。旧トレセン軒とURAの周回は従来のたづな1枠を保持し、シナリオを選択可能。サポカの自前・レンタル表記は表示しない。因子周回の他5枚はSSR・SR・Rから提案・編集
- PCではスキル一覧を2列表示。各スキルに高・中・低の優先度と理由を表示し、絞り込み可能
- キャラは衣装ごとのゲーム内の顔アイコン、サポカは各カードのイラストを表示。サポカ画像の右上にゲームと同じ7種類の得意練習アイコンを表示（合計845点を同梱）。キャラ一覧は顔を上、衣装名・名前を下に配置
- 本育成のキャラ・6枚の編成から、レースごとに必要な継承固有の候補・白因子を表示
- 因子名をタップすると、因子周回のキャラ・編成案・イベント択・優先スキルを表示。周回側は別に編集・保存
- 結果を「継承・白因子」「本育成のスキル」「因子厳選」の順に表示。3つ目の「因子厳選」では不足白因子全体を対象に、SSR・SR・Rから高→中→低の取得経路を優先した周回編成を提案
- 各タブの件数・補足をページ末尾へ移し、「因子厳選」は因子ツリーから表示
- 因子ツリーの6個体に「おすすめローテ」を表示。キャラ別目標を照合し、予約・自動目標・選択分岐・抽選目標を区別したレース日程をポップアップで表示・コピー。育成に使う赤因子は親／祖父母／合計★数と開始時適性をツリーへ常時表示。[仕様と調査資料](docs/factor-rotations.md)
- 親2人・祖父母4人を顔アイコン付きの継承ツリーで表示。継承進化を直接親に優先配置し、各ウマに用意する白因子と6枚の周回編成、フレンド側で探す因子を表示。親・祖父母・フレンド側・イベント択を編集して保存可能
- 6個体それぞれのカード6枚・指定する赤因子・目標星数を一覧表示。距離Sを狙う配分を基本に脚質・バ場の開始時適性を補正し、個体の育成時に使う赤因子と遺伝子の準備も案内。星数・継承は抽選で、所持因子の実測値ではない
- 所持ヒント・イベントと、白因子で補う候補・継承元の表示
- 45枚のカードの詳細イベント択。本育成は金スキル側、因子周回は目的の白スキル側も選択可能
- 金スキルと下位白の区別、同キャラサポートの併用防止
- 継承進化の本人所持・直接親条件、9人／12人の順位条件の区別
- 準備チェック、候補の見送り、シナリオ等の手動取得経路
- 複数プランの端末保存、TXTコピー、JSON書き出し・読み込み
- スマートフォン対応、ホーム画面への追加、初回アクセス後のオフライン利用

2026年10月18日確認。10月チャンミは対象外。2027年1〜3月は公式予定だけ表示し、未発表コースの推奨は出しません。

有力ウマTierは2026年10月19日確認。11月は10月3〜14日の当該開催向けnoteとウマ娘ラボを比較した暫定的な編集評価です。公開日だけでなく本文の対象も照合し、評価差と比較資料が少ない候補を明示します。12月の旧表は撤回し、当該開催向けの新しいnoteを含む比較資料を確認できるまで保留しています。自動更新・実測勝率ではありません。[調査資料と編集方針](docs/character-tier-research.md)

## 起動

Node.js 22以降。外部パッケージのインストールは不要です。

```sh
node tools/serve.mjs
```

ブラウザーで http://127.0.0.1:4173 を開きます。`file://`で直接開くとJSONを読み込めません。

本育成はキャラ・脚質・レースに合わせて推奨サポカを自動セットします。ページ起動時にも公開済みの最新の開催条件・推奨・優先度を読み込み、編成と不足因子を再計算します。各枠は手動変更でき、「推奨に戻す」で再設定、「最新情報を更新」で配信データを再取得できます。追加発表は根拠を確認して配信データに反映する運用です。[自動編成とデータ更新の仕様](docs/main-deck-updates.md)

```sh
node tools/validate-data.mjs
node --test
```

npmがある環境では `npm start`、`npm run check`、`npm test` も使えます。

## GitHub Pages

`dist/`だけで動く静的アプリです。このリポジトリはGitHub Pagesを設定済みで、mainへのpush後にチェック・公開を行います。手動実行もできます。フォークして利用する場合は、Settings → Pages → Sourceを「GitHub Actions」に設定してください。推論・APIキー・バックエンドは不要です。Pagesの利用可否はリポジトリの公開範囲とGitHubプランによります。[GitHub公式手順](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)

## 判定の範囲

優先度は攻略資料に基づく高・中・低の3段階の目安で、勝率や効果量のシミュレーション結果ではありません。全候補の取得を必須とするものでもありません。京都3000mでは右回り・秋ウマ娘を高、京都レース場を低に分けます。真髄・体は消費分も走り切れる持久力を確保する前提で高としています。発動条件や脚質による違い、出典は各スキルの詳細から確認できます。

編成別の因子周回記事は、サポートから取得できるスキルを因子目標から外している場合があります。その順位を取得優先度に直接転用せず、取得優先度と編成から不足する因子候補を別々に判定します。[優先度調査の整理](docs/priority-research.md)

「編成から取得候補」は、所持ヒントの抽選やイベントの条件を満たせば取得できる経路を表します。詳細択が未登録のイベントは「イベント条件を確認」と表示します。白因子候補は登録された取得経路との差分で、因子が必ず発動するという表示ではありません。

本育成では、金スキルと引き換えになる白スキル択を取得経路に含めません。たとえばパワーファインの金スキル側を使う場合、真髄・体は不足因子として残します。因子周回の編成では白スキル択を指定でき、本育成の編成・不足判定・準備済みチェックとは独立して保存します。旧版で本育成に設定した白択も補正します。

本育成はSSRを対象とし、旧保存のSR・Rは本育成の編成を読み込む際に外します。因子周回のSR・Rや、保存プランの原本は保持します。サポカの新しい順はGameToraの実装日を基準にし、同日はカードIDの降順とします。

用途は563枚・631スキルの説明にある対象条件をもとに分類します。限定的な白ヒントだけでカード全体の用途を狭めず、本育成で選べる金スキルの組み合わせを優先します。金スキルの対象が合うことと、レースでの強さ・加速の有効位置は別です。[分類・固定枠の仕様](docs/support-usage.md)

周回の編成案は対象因子と他の不足白因子の取得経路をまとめるための案です。実測の最適編成ではなく、所持・凸数・レースボーナス・相性は評価していません。各カードや周回キャラは変更できます。金スキルの因子化は扱わず、上位スキルを習得できる場合も対象は下位の白因子です。[本育成と因子周回の仕様](docs/factor-workflow.md)

不足全体からの周回提案では、条件未登録のイベントだけにあるスキルをカバー件数から除外します。真髄・体は本育成で優先度「高」のまま、周回では既存因子から継承する前提として別表示し、体だけを理由にパワーファインを採用しません。他の不足を取れるファインや手動指定は使えます。親と祖父母ごとに異なる不足分を補い、高の白因子は両親にも重ねる方針で担当を表示します。共通GⅠは5組の予定勝利からボーナスを集計し、同一GⅠの重複を除いてローテを揃えます。キャラ固有の相性値は未評価です。ツリーは作成・募集する因子の設計案で、所持状況や実在するフレンドの在庫を確認した結果ではありません。継承進化は直接親・対象衣装の本人所持などの条件を別途満たす必要があります。手動調整は本育成の変更後も保持し、現在の不足を再判定して再提案ボタンを表示します。[継承ツリーと網羅提案の仕様](docs/lineage-planner.md)

2026年10月28日の更新で、本育成と駿大祭の周回はSSR吾妻へ変更。旧トレセン軒とURAは従来のたづな1枠を保持します。URAでの固定はシナリオ特効を意味しません。11月京都3000mの自制心は今回に限り中へ変更し、12月の中は維持します。赤因子・遺伝子の準備条件と出典は[個体別の準備方針](docs/factor-targets.md)に記載しています。

キャラの進化スキルの効果量比較や、最終ステータスからの必要回復量の計算は行いません。本育成のシナリオ固有・共通イベント等は自動計上せず、各候補の「別ルートで取得する予定にする」で補います。因子周回では取得方法にURAを選ぶと真髄・体／力／速の対決イベントを候補に加えます。成功・習得・因子化を保証する表示ではありません。

## データ更新

`dist/recommendations.js`に公式開催条件・コース別推奨・参照元、`dist/priorities.js`にコース・脚質別の優先度と理由、`dist/data/catalog.json`にキャラ／サポートとスキルの対応を分離しています。動作時に外部DBを取りに行かないため、提供元の停止で照合が壊れません。

```sh
node tools/update-data.mjs
```

公開DBを`research/`へ取得します。`tools/build-data.mjs`の公開日カットオフ、推奨規則・開催予定を資料と照合して更新してから、次を実行します。

```sh
node tools/build-data.mjs
node tools/download-artwork.mjs
node tools/validate-data.mjs
node --test
```

自動ダウンロードだけではコース条件・推奨・新カードのイベント択は更新されません。出典の日付・現行仕様を確認してください。
